# פרק 20 – ממשק משתמש

## פתיח

פרק זה דן ב**ממשק המשתמש (UI/UX) כסיכום מערכתי** — לאחר
שפרקים 16–19 פירטו את המסכים, האלמנטים, וההודעות. הסעיף 20
בנוהל ההגשה (עמ' 12) דורש *"ממשק משתמש"* כפרק נפרד —
המקום שבו מסבירים את **הבחירות העיצוביות, עקרונות ה-UX,
והרציונל** מאחורי הממשק שתואר.

הפרק מאורגן סביב חמישה צירים: (1) פילוסופיית העיצוב, (2)
ארכיטקטורת המסכים, (3) זרימות משתמש (User Journeys), (4)
התאמת חזותיות לתפקוד, (5) מגבלות ושיפורים עתידיים.

## 20.1 פילוסופיית העיצוב

### 20.1.1 עקרונות מנחים

המערכת מתבססת על **חמישה עקרונות עיצוב מוצהרים**:

1. **חלון יחיד עם תצוגה ראשית מקיפה** — מנעו ריבוי חלונות
   מקבילים שדורשים מהמשתמש לעקוב אחר כמה תהליכים. במקום
   זאת, ה-`JTable` הראשי ב-S1 מציג את כל המידע הקריטי
   בו-זמנית (שם, התקדמות, מהירות, peers, state).

2. **Defaults שעובדים מהקופסה** — `Rarest First` +
   `Tit-for-Tat` הם הברירת מחדל ב-Combo boxes. משתמש שאינו
   מבין באלגוריתמים פשוט לוחץ Add Torrent → בוחר קובץ →
   בוחר תיקייה → ההורדה מתחילה.

3. **שקיפות פנימית בלי הצפה** — ה-Event Log חשוף לחלוטין;
   המשתמש המתעניין רואה את כל הפעולות הפנימיות. המשתמש
   הנינוח יכול להתעלם ממנו (חצי תחתון של ה-`JSplitPane`).

4. **אישור הרסני בלבד** — `JOptionPane.showConfirmDialog`
   מופיע **רק לפני פעולות לא הפיכות** (Cancel, Clear
   History). פעולות הפיכות (Pause/Resume) לא דורשות אישור.

5. **שקט ב-error path** — שגיאות שאינן ביוזמת המשתמש (כשל
   pause/resume שכנראה ייפתר ב-polling הבא) לא מציגות popup;
   רק שגיאות יזומות (Start Download) מציגות popup. הגישה
   מפחיתה הפרעות מיותרות.

### 20.1.2 התאמה לרמות משתמש שונות

הממשק תוכנן לשלוש רמות שונות של ידע משתמש:

- **משתמש קצה רגיל (beginner)**:
  - לוחץ Add Torrent → בוחר קובץ → בוחר תיקייה → רואה
    בטבלה progress bar שצובע מ-כחול לירוק.
  - לא חייב להבין את ה-Algorithm Combos — הם נשארים על
    ברירת המחדל המומלצת.

- **משתמש טכני (intermediate)**:
  - יכול לבחור אלגוריתם אחר ולבדוק את ההשפעה.
  - מסתכל ב-Event Log כדי לראות חיבורי peers וכשלי SHA-1.
  - פותח את History dialog כדי להשוות ביצועים בין הורדות.

- **חוקר אלגוריתמי (advanced)**:
  - משתמש ב-Algorithm Statistics dialog כדי לראות bar chart
    של בחירות rarest-first ו-9 מדדים מצרפיים.
  - מריץ הורדות זוגיות (rarest-first vs random) כדי
    להשוות (כפי שתואר בפרק 5 ויודגם בפרק 24).

## 20.2 ארכיטקטורת המסכים — סיכום מערכתי

המערכת בנויה משלוש שכבות מסכים:

| שכבה | מסכים | תפקיד | מודאליות |
|---|---|---|---|
| **1. עיקרי** | S1 (Main Window) | הציר היחיד שתמיד פתוח | לא-מודאלי (חלון JFrame) |
| **2. כלים** | S5 (History), S7 (Stats) | תצוגה מורחבת של נתונים | non-modal (`JDialog(... , false)`) — אפשר להשאיר פתוח תוך כדי שימוש ב-S1 |

## 20.3 זרימות משתמש (User Journeys)

### 20.3.1 זרימה ראשית: "להוריד torrent"

הזרימה הנפוצה ביותר — 5 לחיצות בלבד מפתיחת האפליקציה ועד
התחלת הורדה:

```
1. הפעלה  (start.sh / start.bat)
     ▼
2. S1 נפתח עם status="Connecting..."
   → תוך 1–2 שניות: "Connected to engine"
     ▼
3. לחיצה על "Add Torrent"  →  S2 נפתח
     ▼
4. בחירת קובץ + Open  →  S3 נפתח
     ▼
5. בחירת תיקייה + Open  →  השרת מקבל POST /torrents
     ▼
6. שורה חדשה בטבלה S1 במצב Running, ProgressBar מתחיל לזוז
```

זמן ביצוע משוער: 15–30 שניות (מרבית הזמן: חיפוש הקובץ
ב-FileChooser).

### 20.3.2 זרימה שנייה: "להשהות ולחדש"

```
1. ב-S1, לחיצה על שורת ההורדה  →  Pause + Cancel נדלקים
2. לחיצה על Pause  →  state = Paused (תוך 500ms)
3. ProgressBar קופא; Speed = 0
4. לחיצה על Resume  →  state = Running שוב
```

זמן ביצוע: < 1 שנייה למחזור.

### 20.3.3 זרימה שלישית: "להשוות אלגוריתמים"

```
1. בחירת Piece=Rarest First, Peer=Tit-for-Tat ב-Combo
2. Add Torrent על קובץ test
3. המתנה להשלמה
4. שינוי Combo ל-Random + Round Robin
5. Add Torrent על אותו קובץ (שוב)
6. המתנה
7. לחיצה על Statistics  →  S7 נפתח
8. בלשונית "General Statistics" השוואת avg_speed,
   peak_speed, choke_cycles
```

זה ה-User Journey שלשמו נבנתה כל המערכת המדידה — הוא מנכיח
את הפרויקט כפרויקט אלגוריתמי-השוואתי.

## 20.4 התאמת חזותיות לתפקוד

### 20.4.1 קודים צבעוניים

המערכת **חסכונית בצבעים** — היא מסתמכת על ה-Look & Feel
המערכתי (`UIManager.setLookAndFeel(UIManager.getSystemLookAndFeelClassName())`)
כדי להיראות כמו אפליקציה נטיבית בכל OS. הצבעים היחידים
שמוגדרים מפורשות:

| צבע | מיקום | משמעות |
|---|---|---|
| `Color(60, 120, 200)` (כחול) | `ProgressBarRenderer` ב-progress < 100% | הורדה פעילה |
| `Color(50, 150, 50)` (ירוק) | `ProgressBarRenderer` ב-progress = 100% | הורדה הושלמה |
| צבעי `JOptionPane` סטנדרטיים | popups | אדום (error), כחול (info), צהוב (question) |
| צבע bar chart ב-`BarChartPanel` | S7 Tab 1 | כחול ייצוגי |

החיסכון בצבעים מבטיח שה-UI נשאר נקי וקריא; הצבעים שהוגדרו
**משמעותיים** (כחול=פעיל, ירוק=מוצלח).

### 20.4.2 פונטים

- **פונט ראשי**: ברירת המחדל של ה-Look & Feel — נטיבי לכל
  OS (Segoe UI ב-Windows, San Francisco ב-macOS, Cantarell/
  DejaVu ב-Linux).
- **פונט המונוספייס** ב-Event Log: `Font.MONOSPACED, PLAIN, 12`
  — קריאת חותמות זמן ושמות peers (IPv4) שורות-שורות.

### 20.4.3 אייקונים

המערכת **אינה משתמשת באייקונים מותאמים** — היא מסתמכת על
האייקונים הסטנדרטיים של `JOptionPane`:
- "i" כחול ל-INFORMATION_MESSAGE.
- "X" אדום ל-ERROR_MESSAGE.
- "?" סגול ל-QUESTION_MESSAGE (showConfirmDialog).

זוהי בחירה מודעת — להימנע מ-overhead של ניהול resource files
ולשמור על תאימות בין OSים.

### 20.4.4 פריסה ויישור

- **RTL טבעי**: כותרת החלון בעברית (`"מערכת שיתוף קבצים
  מבוזרת בסגנון BitTorrent"`) — Swing על Java 11+ תומך
  RTL בכותרת חלון אך לא ב-content; ה-content (טבלה, log)
  הוא LTR טכני כי תוכנו אנגלי-טכני (שמות אלגוריתמים,
  IPs, hash codes).
- **רוחב עמודות מועדף** מותאם לתוכן הצפוי: Name=200 (שמות
  ארוכים), ID=70 (8 תווים), Peers=60 (≤2 ספרות).

## 20.5 נגישות ויעילות

### 20.5.1 קיצורי מקלדת

Swing מספק קיצורים סטנדרטיים מבלי שנדרש קוד נוסף:

- **Tab/Shift+Tab**: ניווט בין רכיבים.
- **ENTER**: הפעלת הכפתור עם default focus ב-popup.
- **ESC**: סגירת `JDialog`/`JOptionPane` (מקובל אך לא מסודר
  בקוד; **שיפור עתידי** — להגדיר במפורש).
- **חיצים** בטבלה: מעבר בין שורות בחירה.

### 20.5.2 רספונסיביות

ה-UI **לעולם לא נחסם** הודות לארכיטקטורה דו-שכבתית:

- **`ScheduledExecutorService`** מתזמן עדכון כל 500ms, אך
  ה-task עצמו רק קורא ל-`SwingUtilities.invokeLater` ל-EDT.
- **כל קריאת HTTP** נעטפת ב-`new Thread(() -> { ... }).start()`
  שמוודא שהפעולה החוסמת לא רצה על ה-EDT.
- **עדכוני טבלה** רצים תמיד דרך `invokeLater` → ה-EDT.

התוצאה: גם בעת קריאת `GET /history` ארוכה או `POST /torrents`
שנתקעת ב-tracker איטי, **החלון נשאר רספונסיבי** — אפשר
לגרור, להזיז, ולחזור עליו.

### 20.5.3 התנהגות בעת ניתוק שרת

אם ה-Python Engine נופל באמצע סשן:
- `apiService.getStatus()` יזרוק חריגה.
- `refreshStatus` יתפוס שקטה (`catch (Exception e) {}` בלי
  הודעה — להימנע מהצפה).
- **הנתונים בטבלה לא ירוקנו** — נשארים מהריענון האחרון.
- בריענון הבא (500ms), אם השרת חזר — הנתונים מתעדכנים שוב
  כרגיל.

זוהי בחירת עיצוב מודעת: **המצב הויזואלי האחרון הוא הטוב
ביותר זמין** — אין סיבה להפחיד את המשתמש עם "Server
disconnected" שעלול להיות חולף.

## 20.6 מגבלות ידועות ושיפורים עתידיים

הסעיף מתעד פערי UI ידועים. שיפורים אלה ייכללו בפרק 26
(פיתוחים עתידיים) בצורה מפורטת יותר:

| מגבלה | השפעה | שיפור עתידי |
|---|---|---|
| ה-Event Log לא נחתך ב-GUI | גידול זיכרון בסשנים ארוכים | הוספת `maxLines=500` ב-`JTextArea` עם trim אוטומטי |
| אין קיצור מקלדת מפורש ל-ESC לסגירת dialogs | חוויית UX לא מושלמת | רישום `Action` ב-`InputMap` של ה-Dialogs |
| ה-Combo בוחר אלגוריתם רק לפני יצירה | אי-אפשר לשנות אלגוריתם תוך הורדה | API חדש: `PATCH /torrents/<id>/algorithm` + Combo חדש בשורה |
| אין preview של תוכן ה-torrent לפני התחלה | המשתמש לא יודע איזה קובץ הוא יוריד | dialog ביניים אחרי S2: שם הקובץ, גודל, מספר pieces, רשימת trackers |
| כפתור ברירת מחדל ב-Confirm popups הוא YES | סיכון ENTER מקרי | להגדיר NO כ-default באמצעות `JOptionPane.OK_CANCEL_OPTION` עם CANCEL כ-default |
| כותרת החלון בעברית — תוכן באנגלית | חוויית RTL לא מלאה | תרגום מלא לעברית + i18n proper |
| אין dark mode | למשתמשים שמעדיפים | החלפת `UIManager.setLookAndFeel` ל-FlatLaf Dark theme |

## 20.7 סיכום הפרק

הפרק חיבר את התמונה הכוללת של ממשק המשתמש:

- **חמישה עקרונות עיצוב** (חלון יחיד, defaults עובדים,
  שקיפות בלי הצפה, אישור הרסני בלבד, שקט ב-error path).
- **שלוש שכבות מסכים** (S1 ראשי, S5/S7 כלים non-modal,
  6 פופאפים מודאליים).
- **שלוש זרימות משתמש אופייניות** (download רגיל,
  pause/resume, השוואת אלגוריתמים).
- **התאמה לרמות משתמש** — מתחילים, מתקדמים, חוקרים.
- **רספונסיביות מובטחת** דרך ארכיטקטורה דו-שכבתית של
  scheduler + thread-per-call.
- **7 שיפורים עתידיים** מתועדים — מ-event log truncation
  ועד dark mode.

הפרק הבא (פרק 21) הוא **פרק הקוד** — דרישות סטנדרטיות,
דוגמאות קוד מתועד, וקטעי קוד של פונקציות מרכזיות.

# 5. מדדי הצלחה למערכת

מדדי ההצלחה של המערכת מחולקים לארבעה קטגוריות: ביצועים,
נכונות, אמינות, וחוויית משתמש.

## ביצועים

| מדד | יעד | מקור |
|---|---|---|
| מהירות הורדה ממוצעת | ≥ 80% מקצב התעבורה האפשרי | `avg_speed` ב-`/stats-summary` |
| מהירות שיא | ≥ 5 MB/s על swarm פעיל | `peak_speed` |
| חיבורי peers ממוצעים | ≥ 10 peers בזמן הורדה פעילה | `avg_peers` |
| יחס rarest-first vs random | תצורה A מהירה פי 1.5 לפחות מ-B | השוואה ב-`/stats-summary` |
| ניצולת CPU | < 10% בעת הורדה פעילה של 1MB/s | `top` / `Task Manager` |

ההשערה המרכזית: **תצורה A (`rarest_first` + `tit_for_tat`)
תהיה מהירה פי 1.5 לפחות מתצורה B (`random` + `round_robin`)**
על swarm זהה — בהתאם לתוצאות של Legout *et al.* (IMC 2006).

## נכונות

| מדד | יעד | מקור |
|---|---|---|
| אחוז כשלי SHA-1 ב-pieces | < 1% מסך ה-pieces | מ-event log |
| אחוז handshakes שמצליחים | > 90% מ-peers שב-tracker | חישוב מ-logs |
| התאמת `info_hash` ב-tracker | 100% | אם נכשל, הקובץ פגום |
| pass של 160 unit tests | 100% | `pytest tests/ -v` |
| תאימות לקוחות BitTorrent אחרים | handshake מוצלח עם qBittorrent ו-Transmission | בדיקה ידנית |

## אמינות

| מדד | יעד | מקור |
|---|---|---|
| crash recovery | המערכת חוזרת לפעולה אחרי kill ו-restart | בדיקה ידנית |
| יציבות לזמן ארוך | ריצה רציפה של 24 שעות בלי דליפת זיכרון | `top` ב-Linux |
| התמודדות עם peers זדוניים | peer שנשלח 3 pieces פגומים — banned תוך 60s | מ-event log |
| התמודדות עם tracker נופל | המערכת ממשיכה לעבוד עם peers שכבר חוברו | בדיקה ידנית |

## חוויית משתמש

| מדד | יעד | מקור |
|---|---|---|
| זמן startup | < 5 שניות מהפעלת `start.sh` עד פתיחת GUI | מדידה |
| רספונסיביות UI | אין UI freeze בעת קריאות API ארוכות | בדיקה ידנית |
| polling latency | סטטוס מתעדכן תוך ≤ 1 שנייה משינוי | מדידה |
| התקנה אוטומטית | משתמש חדש מצליח להתקין מ-`./start.sh` בלי הוראות נוספות | בדיקת UX |
| לוג ברור | משתמש טכני מבין את ה-event log בלי מסמך עזר | בדיקה איכותנית |

## תוצאות בפועל

חלק מהמדדים מבוצעים אמפירית עם הרצת `pytest` (נכונות
unit tests = 100% pass), חלקם דורשים הרצת ניסוי על swarm
חי (פרק 24). הפרק 24 מציג את הפרוטוקול ואת המצב הנוכחי
של הניסויים.

# פרק 7 – תיאור פתרונות קיימים לבעיה

## פתיח

פרק זה סוקר את הפתרונות הקיימים בעולם להפצת תוכן מבוזר ולשיתוף
קבצים, עם דגש מיוחד על מימושי BitTorrent ועל חלופות שאינן
BitTorrent. הפרק הוא **תיאורי-עובדתי** ולא ביקורתי — ניתוח SWOT
והשוואה פורמלית בין החלופות יוצגו בפרק 8 (ניתוח חלופות מערכתי).
מטרת הפרק היא להעניק לקורא **מפת שטח** של הפתרונות הזמינים, להבין
את הגיוון הארכיטקטוני בשוק, ולהציב את Project Gal בתוך נוף זה.

הפרק מאורגן בארבע קבוצות: **לקוחות BitTorrent מרכזיים** (7.1) —
תוכנות Desktop בעלות GUI; **ספריות BitTorrent** (7.2) — קוד תשתיתי
המיועד לשימוש מתכנתים; **גרסאות נגזרות והרחבות** (7.3) — מימושים
שמרחיבים את BitTorrent הקלאסי; ו**חלופות שאינן BitTorrent** (7.4) —
פתרונות הפצת תוכן אחרים, מסחריים ואקדמיים. הפרק נחתם בסקירה של
מימושים לימודיים (7.5) שמשמעותיים להקשר של Project Gal.

## 7.1 לקוחות BitTorrent מרכזיים

תת-סעיף זה סוקר את ארבעת לקוחות ה-BitTorrent הנפוצים ביותר בעולם.
מטרת הסקירה היא לאפיין את **הארכיטקטורה**, **שפות הפיתוח**,
**הפיצ'רים המרכזיים** ו**אופן הפצתם**.

### 7.1.1 qBittorrent

- **שפת פיתוח**: C++ (ליבת המנוע), C++ עם Qt (GUI).
- **רישיון**: GPLv2 (קוד פתוח חופשי).
- **ארכיטקטורה**: לקוח Desktop מונוליטי. ליבת ה-BitTorrent מבוססת
  על ספריית `libtorrent-rasterbar` (ראה 7.2.1). שכבת ה-GUI מבוססת
  על Qt5/Qt6 — framework רב-פלטפורמתי שמספק רכיבי UI נטיביים.
- **פלטפורמות**: Windows, macOS, Linux, FreeBSD. גרסה Web-UI חשופה
  כשרת מקומי לניהול מרחוק.
- **פיצ'רים מרכזיים**:
  - תמיכה ב-BitTorrent v1 ו-v2.
  - DHT, PEX, LSD (Local Service Discovery).
  - הצפנת תעבורה (MSE/PE).
  - הגבלת רוחב פס.
  - תור הורדות עם עדיפויות.
  - תמיכה ב-magnet links.
  - חיפוש torrents משולב.
  - WebUI נפרד למשתמשים מתקדמים.
- **קהל יעד**: משתמש קצה מתקדם המעוניין בלקוח חינמי וללא פרסומות.
- **מספר משתמשים**: מוערך בעשרות מיליונים בעולם.

**מאפיין ארכיטקטוני בולט**: כל הקוד מהודר ל-binary יחיד, ללא הפרדה
בין מנוע ל-GUI. אין REST API מובנה (קיים WebUI הנותן ממשק
HTTP פנימי). זוהי **ארכיטקטורה אינטגרטיבית**, השונה
מהותית מהארכיטקטורה הדו-תהליכית של Project Gal.

### 7.1.2 Transmission

- **שפת פיתוח**: C (ליבת המנוע), GTK/Cocoa/Qt (לפי הפלטפורמה).
- **רישיון**: GPLv2/v3 (קוד פתוח חופשי).
- **ארכיטקטורה**: לקוח BitTorrent מינימליסטי במופגן. הליבה כתובה
  ב-C עם דגש על יעילות וצריכת זיכרון נמוכה. GUI נפרדים לכל פלטפורמה,
  המתקשרים עם הליבה דרך RPC מקומי.
- **פלטפורמות**: macOS (נטיבי, ברירת המחדל), Linux, Windows, BSD.
  משמש כברירת המחדל ב-Ubuntu.
- **פיצ'רים מרכזיים**:
  - DHT, PEX, LSD.
  - הצפנה.
  - תור הורדות פשוט.
  - תמיכה ב-magnet links.
  - דמון רקע (`transmission-daemon`) לעבודה ללא GUI.
  - RPC ב-JSON-RPC מעל HTTP — מאפשר שליטה מרחוק ו-CLI.
  - תמיכה ב-IPv6.
- **קהל יעד**: משתמשי macOS וניוצרי Linux המעוניינים בלקוח קל
  ויעיל.

**מאפיין ארכיטקטוני בולט**: הפרדה ברורה בין `transmission-daemon`
(הליבה) לבין `transmission-gtk`/`transmission-mac` (ה-GUI), המתקשרים
דרך **RPC**. דמיון מבני ל-Project Gal: שתי תהליכים נפרדים
המתקשרים דרך REST/RPC. ההבדל: ב-Transmission שני הצדדים כתובים
ב-C, וב-Project Gal — בשפות שונות.

### 7.1.3 Deluge

- **שפת פיתוח**: Python (גם ליבה וגם GUI), GTK ל-UI.
- **רישיון**: GPLv3.
- **ארכיטקטורה**: אדריכלות **client-server** מובהקת. ה-`deluged`
  הוא דמון רקע המבצע את כל לוגיקת ה-BitTorrent (מבוסס על
  libtorrent-rasterbar). שלושה ממשקי משתמש שונים מתקשרים איתו דרך
  Twisted RPC:
  - `deluge-gtk` — GTK-based desktop client.
  - `deluge-console` — text-based.
  - `deluge-web` — web client.
- **פלטפורמות**: Linux בעיקר, גם Windows ו-macOS.
- **פיצ'רים מרכזיים**:
  - מערכת *plugins* מובנית — תוספים שכתובים ב-Python ומשנים
    התנהגות.
  - תמיכה ב-magnet links, DHT, PEX.
  - אדריכלות מפוצלת המתאימה לשרתי headless.
- **קהל יעד**: משתמשי seedbox ושרתים headless.

**מאפיין ארכיטקטוני בולט**: זוהי הדוגמה הטובה ביותר ל**אדריכלות
דו-תהליכית** בעולם ה-BitTorrent, ודומה לארכיטקטורה של Project Gal,
אם כי Deluge משתמש ב-Twisted RPC (פרוטוקול בינארי custom) במקום
ב-REST. בנוסף, גם הליבה וגם ה-GUI כתובים ב-Python — אין הפרדת שפות.

### 7.1.4 μTorrent (uTorrent)

- **שפת פיתוח**: C++.
- **רישיון**: proprietary (סגור). יש גרסאות חינמיות (במודל פרסומות)
  וגרסה משלמת.
- **ארכיטקטורה**: לקוח Desktop מונוליטי. הוא נחשב היסטורית ל"לקוח
  הקל ביותר" — קובץ binary בגודל ~2MB.
- **פלטפורמות**: Windows (עיקרי), macOS, Linux (חלקית), Android.
- **פיצ'רים מרכזיים**:
  - גודל זעיר ויעילות זיכרון.
  - תמיכה מלאה בכל הרחבות BitTorrent הראשיות.
  - מקור חלק מהרחבות (כמו μTP — UDP-based Transport Protocol).
- **קהל יעד**: משתמשי קצה בעידן הזהב של BitTorrent.
- **מצב נוכחי**: איבד פופולריות לאחר הוספת פרסומות וטענות על
  cryptominer מוסתר ב-2015. כיום הקהילה ברובה עברה ל-qBittorrent.

**מאפיין ארכיטקטוני בולט**: דוגמה היסטורית להשפעה של מסחור על
מוצר טכני. רלוונטי ל-Project Gal כדוגמה לכך שאיכות **ארכיטקטונית
ואתית** חשובה לא פחות מאיכות פונקציונלית.

### 7.1.5 השוואה תמציתית

| תכונה | qBittorrent | Transmission | Deluge | μTorrent |
|---|---|---|---|---|
| שפת ליבה | C++ | C | Python | C++ |
| GUI | Qt (C++) | GTK/Cocoa/Qt (C) | GTK (Python) | C++ |
| הפרדת תהליכים | אין | יש (daemon + GUI) | יש (daemon + GUI) | אין |
| RPC/API | רק WebUI | JSON-RPC | Twisted RPC | אין |
| רישיון | GPLv2 | GPLv2/v3 | GPLv3 | proprietary |
| שילוב שפות | אין | אין | אין | אין |

מסקנה: **אף אחד מהלקוחות המרכזיים אינו משלב שתי שפות תכנות שונות
ברמת מנוע ו-GUI**. זהו ייחוד ארכיטקטוני של Project Gal הנובע
מדרישת המחוון.

## 7.2 ספריות BitTorrent

לקוחות BitTorrent מסחריים רבים אינם מממשים את הפרוטוקול בעצמם —
הם משתמשים בספריות תשתית מוכנות. סקירת הספריות חשובה כדי להבין
מה Project Gal לא משתמש בו (ולמה).

### 7.2.1 libtorrent-rasterbar

- **שפת פיתוח**: C++ (תאימות ל-C++11 ומעלה).
- **רישיון**: BSD-3-Clause.
- **שימוש**: ליבת qBittorrent, Deluge, ו-LibreOffice's online updater.
- **תכונות**:
  - מימוש מלא של BEP-3 וכל ההרחבות העיקריות (DHT, PEX, MSE, μTP,
    BitTorrent v2).
  - Bindings ל-Python (`libtorrent-python`) ול-Java
    (`libtorrent4j`).
  - אופטימיזציות מתקדמות (zero-copy I/O, in-memory caching).

זוהי הספרייה ה**המקובלת ביותר בתעשייה**, ומחזיקה ~80% מהשוק
הצרכני של BitTorrent. שימוש בה בפרויקט גמר היה **דחיית כל לוגיקת
הליבה לקוד חיצוני** — בדיוק מה שהמחוון אוסר עליו (סעיף 4 בעמ' 2:
*"אם הפרויקט כולו מורכב מ-API אחד לפתרון ליבת הבעיה ללא אינטגרציה
— זוהי עילה למתן ציון נכשל"*). לכן Project Gal **אינו** משתמש בה.

### 7.2.2 BitTorrent.NET / MonoTorrent

- **שפת פיתוח**: C# (.NET).
- **רישיון**: MIT.
- **תכונות**: מימוש BitTorrent ב-pure managed C#. תאימות ל-.NET
  Framework, Mono, ו-.NET Core.
- **שימוש**: לקוחות שונים על בסיס .NET.

ספרייה זו הייתה רלוונטית אילו פיתחתי GUI ב-C# במקום Java. בחירת
Java נשענת על שיקולים אחרים (ראה פרק 9), ולכן MonoTorrent אינה
רלוונטית לפרויקט.

### 7.2.3 ספריות Python: libtorrent-python, pyrate, btpy

- **libtorrent-python**: Python binding ל-libtorrent-rasterbar.
  עוטף את כל פונקציונליות C++ בקריאות Pythoniic.
- **pyrate, btpy**: ספריות BitTorrent ב-pure Python. פחות
  מתחזקות, ואיכותן משתנה.

שוב, שימוש בספרייה כזו ב-Project Gal היה הופך אותו ל"חזית מעל
spec ידוע", במקום מימוש מאפס.

### 7.2.4 פרקטיקת ה"ספרייה" בעולם BitTorrent

הדפוס שחוזר: **לקוחות מסחריים משתמשים בספרייה אחת** (כמעט תמיד
libtorrent-rasterbar), ומשקיעים את האנרגיה שלהם ב-GUI, ב-pipeline
הניהול ובחוויית המשתמש. הסיבות: מורכבות הפרוטוקול גבוהה,
האופטימיזציות אקזוטיות, ו-edge cases רבים שלוקח שנים לסגור.
Project Gal יוצא דופן בכך שהוא חוזר ומממש את כל זאת — דווקא משום
שזהו פרויקט לימודי שמטרתו להראות הבנה עמוקה ולא לבנות מוצר מסחרי.

## 7.3 גרסאות נגזרות והרחבות של BitTorrent

תת-סעיף זה מציג מימושים שמרחיבים את BitTorrent הקלאסי או מנתבים
אותו לסביבות חדשות.

### 7.3.1 WebTorrent

- **תיאור**: מימוש BitTorrent מעל **WebRTC** במקום TCP. רץ
  בדפדפן ללא ספרייה native.
- **שפת פיתוח**: JavaScript (Node.js לצד שרת).
- **רישיון**: MIT.
- **חשיבות**: מאפשר torrenting מתוך דף web, פותח עולם של שימושים
  ב-streaming, ב-archival, וב-CDN distributed. דוגמאות שימוש:
  PeerTube (פלטפורמת וידאו מבוזרת), Internet Archive (גיבוי
  מבוזר).
- **מגבלה**: עובד רק עם clients אחרים של WebTorrent, **אינו תואם
  ל-BitTorrent v1 רגיל** (מאחר שמשתמש ב-WebRTC במקום ב-TCP).

WebTorrent הוא דוגמה לשאיפת *interoperability* באקוסיסטם —
ויחד עם זאת לאתגר השפעת התשתית על הפרוטוקול.

### 7.3.2 BitTorrent v2 (BEP-52)

- **תיאור**: רביזיה משמעותית של הפרוטוקול, פורסמה ב-2017 ועברה
  ל-status "final" ב-2020.
- **שינויים מרכזיים**:
  - SHA-1 → **SHA-256** לכל פונקציות ה-hash (כולל `info_hash`).
  - תמיכה ב-**merkle trees** לאימות יעיל של חלקי piece (לא רק
    piece שלם).
  - מבנה חדש של מילון `info` עם תמיכה טבעית בקבצים גדולים מאוד
    (>1TB).
  - תאימות קדמית חלקית בלבד עם v1.
- **קצב אימוץ**: איטי. ב-2024 רק חלק מהלקוחות תומכים מלא ב-v2.

חשיבות לפרויקט: Project Gal **אינו** מממש את v2 (זה היה מכפיל
את היקף העבודה). תמיכה ב-v2 רשומה כפיתוח עתידי בפרק 26.

### 7.3.3 BitTorrent over Tor (אנונימי)

- **תיאור**: שימוש ב-BitTorrent מעל רשת Tor להפצת אנונימית.
- **בעיה**: BitTorrent רגיל אינו מתאים ל-Tor — חשיפת ה-IP מתבצעת
  ברמת ה-tracker, ולא רק ברמת ה-TCP. דורש שיטות נוספות לאנונימיות
  אמיתית.

לא רלוונטי ל-Project Gal לימודית, אך מהווה דוגמה לאתגרי פרטיות
ב-P2P.

## 7.4 חלופות שאינן BitTorrent

תת-סעיף זה מציג גישות הפצת תוכן שונות מ-BitTorrent.

### 7.4.1 HTTP/HTTPS Direct Download

- **תיאור**: הפצת קבצים משרת HTTP יחיד או רשת שרתים.
- **ארכיטקטורה**: Client-Server קלאסי.
- **חוזקות**: פשוט להבין, פשוט להפעיל, תמיכה אוניברסלית
  בדפדפנים.
- **חולשות**: צוואר בקבוק, נקודת כשל יחידה, עלות גבוהה למפיץ.

זוהי **חלופה A** בניתוח הפורמלי בפרק 8.

### 7.4.2 Content Delivery Networks (CDN)

- **תיאור**: רשת שרתי מטמון מבוזרים גיאוגרפית (CloudFlare, Akamai,
  AWS CloudFront, Fastly).
- **ארכיטקטורה**: שרת מקור יחיד + עשרות / מאות edge servers
  ברחבי העולם.
- **חוזקות**: סקלביליות מצוינת, השהיה נמוכה, עמידות לעומסים.
- **חולשות**: עלות גבוהה, תלות בספק מסחרי, אינו "מבוזר
  אמיתית" (יש בעלים).

זוהי **חלופה C** בניתוח בפרק 8.

### 7.4.3 IPFS (InterPlanetary File System)

- **תיאור**: פרוטוקול תקשורת מבוזר ל-"web מבוזר".
- **ארכיטקטורה**: content addressing (כל קובץ מזוהה ב-hash שלו),
  DHT לחיפוש peers, BitSwap לחילופי בלוקים.
- **שפת פיתוח**: Go (`go-ipfs`/`kubo`), JavaScript (`js-ipfs`).
- **השוואה ל-BitTorrent**:
  - דמיון: content-addressed, DHT-based discovery, peer-to-peer
    transfer.
  - שוני: IPFS אינו מבוסס על swarm בודד; הוא רשת אחת גלובלית
    שלוקחת חלק בכל ההפצות. IPFS גם משתלב עם blockchain (Filecoin)
    לתמרוץ אחסון.
- **שימושים**: NFTs, archival, censorship-resistant publishing.

IPFS הוא הצד המודרני של רעיון ה-P2P, ומציג כיוון אפשרי לעתיד
הפצת תוכן.

### 7.4.4 Resilio Sync (לשעבר BitTorrent Sync)

- **תיאור**: סנכרון קבצים בין מכשירים, מבוסס על טכנולוגיית
  BitTorrent.
- **שפת פיתוח**: C++, proprietary.
- **שימוש**: סנכרון אישי וצוותי, חלופה ל-Dropbox.

מציג שימוש מעניין בטכנולוגיית BitTorrent מחוץ להפצת תוכן ציבורי.

### 7.4.5 פתרונות הפצה ארגוניים: Twitter Murder, Facebook Wormhole

- **תיאור**: פתרונות פנים-ארגוניים להפצת deployments / קבצים בין
  אלפי שרתים, מבוססים על עקרונות BitTorrent.
- **דוגמאות**:
  - **Twitter Murder** (2010): פתרון BitTorrent פנימי להפצת
    deployments. צמצם זמני deploy מ-40 דקות ל-12 שניות בקלאסטרים
    גדולים.
  - **Facebook Wormhole**: דומה ל-Murder, מותאם לסביבת
    Facebook.
- **שפת פיתוח**: בדרך כלל Python (Murder היה Python).

מעניין בהקשר של Project Gal: שני הפתרונות הללו השתמשו ב-Python
לליבת ה-BitTorrent, בדומה לבחירת Python במנוע Project Gal.

## 7.5 מימושים לימודיים של BitTorrent

תת-סעיף זה רלוונטי במיוחד ל-Project Gal, מאחר שמסמן את הסביבה
הקרובה ביותר אליו.

### 7.5.1 פרויקטים אקדמיים ב-GitHub

חיפוש מהיר ב-GitHub חושף **מאות מימושים לימודיים** של BitTorrent,
ברמות איכות וסקופ משתנים. דפוסים נפוצים:

- **שפת פיתוח**: Python (~50%), Go (~20%), C++ (~10%), Java
  (~10%), אחר (~10%).
- **מבנה אופייני**: קובץ יחיד או 3–5 קבצים. מעט מאוד מימושים
  אקדמיים כוללים GUI נפרד.
- **רמת מימוש**: רובם מתעצרים לאחר handshake ו-bitfield, ללא
  מימוש מלא של rarest-first או choke/unchoke.
- **טסטים**: בדרך כלל אין או מינימליים.

### 7.5.2 קורסים אוניברסיטאיים

מספר אוניברסיטאות (MIT 6.824, Stanford CS244B, NYU Distributed
Systems) משתמשות ב-BitTorrent כפרויקט סמסטריאלי לקורסי distributed
systems. הפרויקטים בקורסים אלה הם בקנה מידה דומה ל-Project Gal —
מימוש מאפס של BEP-3 — אך לעיתים בלי GUI ובלי שיוך בין שתי שפות.

## 7.6 מיקום Project Gal בנוף הפתרונות הקיימים

לסיכום הסקירה, מיקום Project Gal:

- **לעומת qBittorrent / Transmission / Deluge**: Project Gal הוא
  פרויקט לימודי, לא מוצר ייצור. חסר ב-Project Gal פיצ'רים שאינם
  ליבת הפרוטוקול (DHT, PEX, MSE, magnet links, BitTorrent v2). הם
  רשומים כפיתוחים עתידיים בפרק 26.
- **לעומת libtorrent-rasterbar**: Project Gal הוא **מימוש מאפס**.
  הוא אינו מתחרה בliblibrary של libtorrent כספרייה לשימוש כללי, אלא
  כתוצר חינוכי המראה הבנה עמוקה.
- **לעומת WebTorrent**: שונה מהותית — Project Gal פועל מעל TCP
  ולא WebRTC, ותומך בפרוטוקול הקלאסי.
- **לעומת IPFS**: שני העולמות שונים. IPFS הוא רשת אחת גלובלית;
  Project Gal הוא לקוח BitTorrent קלאסי שמתחבר ל-swarm-ים נפרדים.
- **לעומת מימושים אקדמיים אחרים**: Project Gal **בולט** בעומק
  המימוש, ב-GUI הנפרד, באינטגרציה הרב-לשונית, ובמבנה הטסטים.

## סיכום הפרק

פרק זה הציג מפת שטח מקיפה של פתרונות קיימים להפצת תוכן ושיתוף
קבצים — לקוחות BitTorrent מרכזיים (qBittorrent, Transmission,
Deluge, μTorrent); ספריות תשתית (libtorrent, MonoTorrent); גרסאות
נגזרות (WebTorrent, BitTorrent v2); וחלופות שאינן BitTorrent
(HTTP/CDN, IPFS, Resilio Sync, פתרונות ארגוניים). הפרק נחתם בסקירה
מפורטת של מימושים לימודיים, שמהווה את ההקשר הקרוב ביותר ל-Project
Gal.

הסקירה היא **תיאורית בלבד** — היא מציגה את הנופים אך אינה שופטת
ביניהם. בפרק הבא (פרק 8) ייערך **ניתוח חלופות מערכתי** פורמלי
עם טבלאות SWOT, שעל בסיסו תוצדק הבחירה ב-BitTorrent כפתרון
(פרק 9).
